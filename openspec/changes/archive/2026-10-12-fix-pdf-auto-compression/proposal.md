## Why

The default (`auto`) PDF compression in scantpaper produces files roughly
twice the size of gscan2pdf for the same scan. The cause is that `auto` is
never interpreted: gscan2pdf resolves `auto` per image type and re-encodes
colour at the selected JPEG quality, whereas scantpaper embeds the stored
JPEG (hard-coded quality 92) verbatim and ignores the save dialog's quality
setting. Bilevel pages are also emitted as Flate rather than CCITT G4, and
the explicit G3/G4 options do not actually produce G4. The result is a
silent regression against gscan2pdf that users see as bloated PDFs.

## What Changes

- Implement `auto` PDF image compression: resolve a concrete codec for each
  page from its image properties.
- Encode bilevel pages with CCITT Group 4 (the smallest lossless encoding
  for scanned text), both for `auto` and for the explicit G3/G4 options.
- Apply the save dialog's JPEG quality setting to PDF JPEG output, so
  changing it changes the output (today it has no effect).
- Encode continuous-tone pages that are not already JPEG as JPEG at the
  configured quality when JPEG is selected, rather than falling back to
  Flate.
- Pass through an original imported JPEG unchanged when `auto` selects
  JPEG, so imported images are not needlessly re-compressed (an improvement
  over gscan2pdf, which always re-encodes colour).
- Persist, per stored image, whether it is an untouched imported original or
  was generated by scantpaper, so the two can be told apart after a session
  is saved and reloaded. Images in existing sessions default to "generated".
- Leave the in-session storage format (quality-92 JPEG for continuous-tone,
  PNG for bilevel/transparency) unchanged, so editing fidelity is preserved.

## Capabilities

### New Capabilities

- `pdf-image-compression`: how page images are encoded when writing a PDF -
  automatic per-image codec selection, the JPEG quality applied to output,
  CCITT G4 for bilevel pages, and when an already-encoded image is embedded
  without re-encoding.

### Modified Capabilities

- `image-storage-format`: the PDF-save passthrough requirement is narrowed
  so that only original imported images are embedded verbatim; images that
  scantpaper generated (scans and edited pages) are compressed according to
  the selected output compression.

## Impact

- `src/scantpaper/page.py` (`write_image_for_pdf`, encoding helpers).
- `src/scantpaper/savethread.py` (PDF assembly, temp-file format).
- `src/scantpaper/docthread.py` (persist image provenance; schema version
  bump and migration).
- `src/scantpaper/file_menu_mixins.py`, `src/scantpaper/tools_menu_mixins.py`
  (pass quality/compression through the save options).
- `src/scantpaper/dialog/save.py`, `src/scantpaper/config.py` (defaults and
  option plumbing).
- Tests under `src/scantpaper/tests/`, and `README.md` where the save
  options are documented.
